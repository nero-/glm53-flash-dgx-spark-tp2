# Run 04 — mtp3 @ batch 8192, 7 GiB pin, 512k context (PP max)

Date: 2026-09-03 · Image: `local/vllm:glm53-flash-nvfp4-R17-roce` · Profile:
`rank-0-8192.env` / `rank-1-8192.env`.

## Goal
The ~2k prefill target. Their notes: batch 8192 measured +15-25% prefill
over 4096, at the cost of ~3 GiB more activation peak. John's directive:
8192 with less context, pinned KV, to keep off the OOM edge.

## Config (deltas vs run 02)
`MAX_NUM_BATCHED_TOKENS=8192` (was 4096) · KV pin **7 GiB** (7516192768,
was 10 GiB) · `MAX_MODEL_LEN=524288` (was 1048576). Everything else
unchanged: mtp@3 adaptive, vision 4/1, seqs 8, capture 96, piecewise
graphs, fp8 KV, instanttensor, B12X + HUMMING.

Pinned (not unpinned): her notes say the profiler goes negative with
vision + 8192 + piecewise graphs — the pinned path is the only safe one at
this batch.

## Boot
Healthy in ~3 min. **GPU KV cache: 961,194 tokens** (7.8 KiB/token at this
batch profile; 1.83× at 512k). Memory during bench: r0 119 / r1 115 GiB
used — same envelope as run 02, no OOM anywhere.

## Trade + takeaway
- Batch 8192 + 7 GiB pin = **~1.85-1.96k PP** with **961k KV** (vs 1.47M
  at 4096/10 GiB). The pin/batch trade is visible: each GiB of pin freed
  buys the +3 GiB activation workspace.
- If both targets are wanted in one profile: pin **7.5 GiB** → ~1.03M KV
  tokens at 8192 (only +0.5 GiB over this proven run).
- Daily driver recommendation: this profile for throughput (PP ~2k, 961k
  KV), or run 02's profile for maximum KV (1.47M) at PP 1.81k.
